# Swipe-go UI 设计记录

## 当前阶段

需求规划中，未开始产品代码实现。用户要求先查看回顾页的新 UI，再继续共同规划。

## 用户已确认

- 第一版仅 iPhone。
- 默认随机选择一段连续时光，保留照片和视频上下文。
- 同时满足回顾与人工确认清理，担心误删。
- 第一版四屏概念方向可接受；不能把静态稿认可当作已完成产品验收。
- 最新回顾页要求：默认只有照片；左滑下一张，右滑上一张；上滑加入待删，下滑收藏；点击照片顶部区域展开功能按钮。

## 设计稿

- [初版四屏概念](ui-overview-v1.png)：首页、回顾、相似照片比较、删除前复核。
- [沉浸回顾 v2](immersive-review-v2.png)：纯照片、顶部操作面板展开、待删短暂反馈三个状态。最新稿待用户反馈。
- 使用内置 imagegen 创建静态位图；照片为生成的示意素材，不是用户图库。
- v2 提示词要点：保持海边回顾视觉，移除常驻状态栏、标题、缩略图与底部操作栏；顶部点按展开半透明功能面板；上滑仅标记待删，以短暂可撤销提示反馈；手势说明放在手机外部。

## 设计建议与待确认细节

- 建议：顶部再次点按或关闭按钮收起面板；上滑后短暂提示“已加入待删 / 原件仍在相册”，支持撤销。
- 待确认：收藏或待删后是否自动前进；已收藏照片再下滑是否取消收藏；上滑已收藏项如何处理。
- 待确认：视频播放/暂停、进度与声音控制；横向照片采用完整显示还是裁切；首次手势教学与无障碍按钮入口。
- 实现前需要验证手势与系统边缘手势、图片缩放、视频拖动的冲突。
- 这里的全屏竖图只是示例，不能推导为允许默认裁切任何原片。
